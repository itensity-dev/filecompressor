# FileCompressor

Бесплатный сервис для сжатия и конвертации файлов (PDF, JPG, PNG, WebP, AVIF, HEIC), который **работает целиком в браузере пользователя**. Файлы не загружаются на сервер, поэтому сервер почти не нагружен и ничего не хранит.

## Главный вопрос: можно ли не нагружать сервер и не хранить данные?

Да. Именно так и устроен проект:

```
 Браузер пользователя                                   Ваш «сервер» (CDN)
┌──────────────────────────────────────────────┐        ┌─────────────────────┐
│  страница (HTML/CSS/JS)  ◄─────────────────────────────│ статические файлы   │
│  кодеки WebAssembly      ◄─────────────────────────────│ (HTML, JS, .wasm)   │
│                                              │        └─────────────────────┘
│  файл пользователя ──► Web Worker ──► результат       ▲
│      (никуда не уходит)  MozJPEG / oxipng /   │        │  пользовательских файлов
│                          libwebp / libavif /  │        │  здесь нет вообще
│                          pdf-lib / pdf.js     │
└──────────────────────────────────────────────┘
```

- **Сервер раздаёт только статику**: HTML, JS и `.wasm`. Её кеширует CDN, и после первого визита большая часть берётся из кеша браузера. Нет бэкенда, базы данных и очередей задач.
- **Обработку выполняет устройство пользователя**: кодеки скомпилированы в WebAssembly и работают в Web Workers на всех ядрах процессора.
- **Хранить нечего**: файлы не покидают устройство. Это легко проверить: вкладка Network в DevTools пустая, после загрузки страницы можно отключить интернет. Дополнительно Content Security Policy (`connect-src 'self'`) технически запрещает странице и воркерам отправлять данные на другие сайты, даже если в зависимость попадёт вредоносный код.
- **Стоимость**: на Cloudflare Pages статический хостинг бесплатен, без лимита по трафику. Платить нужно только за домен (~$10 в год). Поэтому сервис может оставаться бесплатным без ограничений.

## Что умеет

**Сжатие:** PDF (3 уровня + «в ч/б»), изображения (JPG/PNG/WebP/AVIF со сменой формата), JPG (MozJPEG), PNG (умная палитра до 256 цветов + oxipng или без потерь), WebP.

**Конвертация:** полная матрица «откуда → куда», у каждой пары своя страница:

| Из \ В | JPG | PNG | WebP | AVIF | PDF |
|---|---|---|---|---|---|
| HEIC | ✓ | ✓ | ✓ | ✓ | ✓ |
| JPG | | ✓ | ✓ | ✓ | ✓ |
| PNG | ✓ | | ✓ | ✓ | ✓ |
| WebP | ✓ | ✓ | | ✓ | ✓ |
| AVIF | ✓ | ✓ | ✓ | | ✓ |
| PDF | ✓ | ✓ | | | |

Плюс универсальный «Конвертер изображений». На любой странице конвертации целевой формат переключается прямо в панели (JPG / PNG / WebP / AVIF), и файлы сразу пересчитываются. Картинки → PDF: порядок страниц, A4/Letter/по размеру изображения. PDF → картинки: 72–300 DPI.

Удобства, которых у конкурентов обычно нет:

- **Пакетная обработка без лимитов**: сколько угодно файлов, параллельно на всех ядрах.
- **Drag & drop в любое место страницы** и **вставка из буфера (Ctrl+V)**, например скриншота.
- **Сравнение «до/после»** со слайдером.
- **Результат никогда не хуже исходника**: если сжать не получилось, отдаётся оригинал, а не файл большего размера.
- **Метаданные удаляются** (GPS, модель камеры), ориентация фото при этом сохраняется.
- **Изменение размера** по длинной стороне, **скачивание всего одним ZIP**.
- **Работает офлайн** и ставится как приложение (PWA).
- **Настройки запоминаются** в браузере, «Применить ко всем» после их изменения.
- **Светлая и тёмная тема**: по умолчанию следует системе, выбор запоминается и применяется до отрисовки страницы (без «мигания»).
- Без регистрации, рекламы, водяных знаков, cookies и трекеров.

## Совместимость с устройствами

Работает в браузерах примерно с 2023 года и новее, на компьютерах, телефонах и планшетах:

| Платформа | Минимум |
|---|---|
| iPhone / iPad (Safari и любые браузеры на iOS) | iOS / iPadOS 16.4 (iPhone 8 и новее) |
| Android | Chrome 111+ (Samsung Internet, Яндекс Браузер и др. на актуальном Chromium) |
| Windows / macOS / Linux | Chrome / Edge 111+, Firefox 114+, Safari 16.4+ |

Что сделано, чтобы работало и на телефонах:

- **Лимит canvas в Safari на iPhone** (~16,7 Мп: фото iPhone 15/16 весят 24 Мп). Safari молча отдаёт пустые пиксели, поэтому каждый canvas проверяется перед использованием, а большие фото декодируются WebAssembly-декодером без ограничений. HEIC в таком случае аккуратно уменьшается до допустимого размера. Регрессионный тест имитирует это поведение Safari.
- **Память**: на телефонах параллельно работают максимум 2 воркера, на устройствах с ≤2 ГБ ОЗУ — 1, чтобы iOS не перезагружала вкладку.
- **PDF → картинки** рендерится не больше 16 Мп на страницу (A4 при 300 DPI = 8,7 Мп) и использует legacy-сборку pdf.js с полифиллами.
- **Старый браузер или выключенный WebAssembly** (например, режим блокировки на iPhone): вместо молчаливой поломки показывается понятное сообщение на языке страницы.
- На сенсорных экранах скрыта подсказка про Ctrl+V.

E2E-тесты запускаются в трёх профилях: десктоп, Android (Pixel 7) и экран iPhone (эмуляция в Chromium). Настоящего движка WebKit в этой среде нет. **Перед запуском проверьте на реальном iPhone** (особенно HEIC → JPG) и на недорогом Android, например через BrowserStack или на своих устройствах.

Известные ограничения: встроенные браузеры Instagram/Facebook на iOS могут не давать скачивать файлы (помогает «Открыть в Safari»). Очень большие файлы ограничены памятью устройства.

## Безопасность

- Файлы не передаются по сети (см. выше), это главная гарантия.
- CSP в `<meta>` с хешами скриптов (генерирует Astro) плюс HTTP-заголовки в `public/_headers`: `connect-src 'self'`, `frame-ancestors 'none'`, `object-src 'none'`, `form-action 'none'`, HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, COOP/CORP.
- Сторонних скриптов, шрифтов и CDN нет: всё отдаётся с вашего домена.
- Встроенный JavaScript в PDF не выполняется (модуль скриптинга pdf.js даже не копируется).
- Зашифрованные PDF не ломаются, пользователь видит понятное сообщение.

## SEO и видимость в LLM

Что уже сделано:

- **218 статических страниц** (7 языков × 29 инструментов + главная и «Как это работает»). HTML полностью отрендерен на этапе сборки, поисковику не нужно выполнять JS.
- У каждого инструмента своя посадочная страница под конкретный запрос («сжать pdf», «heic в jpg», «jpg в pdf»…): уникальные title/description, H1, описание, «как пользоваться», блок про форматы, FAQ, связанные инструменты (перелинковка).
- `hreflang` для всех языков + `x-default`, canonical, `sitemap.xml` с альтернативными языковыми версиями, `robots.txt`.
- Микроразметка JSON-LD: `WebApplication` (бесплатно, `price: 0`), `FAQPage`, `BreadcrumbList`, `WebSite`.
- Open Graph и Twitter Card с картинкой 1200×630.
- **Для LLM**: `/llms.txt` (стандарт llmstxt.org) с фактами о сервисе и списком инструментов; в `robots.txt` явно разрешены GPTBot, OAI-SearchBot, ClaudeBot, PerplexityBot, Google-Extended и др.; FAQ с прямыми ответами, которые модели охотно цитируют; страница «Как это работает».
- Скорость (Core Web Vitals): при загрузке страницы ~40 КБ JS, тяжёлые кодеки подгружаются только когда нужны, системные шрифты, нет сторонних запросов.

Что сделать после деплоя (это нельзя сделать кодом):

1. Подключить домен и указать `SITE_URL` (см. «Деплой»).
2. Добавить сайт и отправить `sitemap.xml` в **Google Search Console**, **Bing Webmaster Tools** (поиск ChatGPT и Copilot опирается на индекс Bing) и **Яндекс Вебмастер** (для русской аудитории).
3. Получить первые внешние ссылки: Product Hunt, Hacker News («Show HN»), Reddit (r/privacy, r/webdev), Habr, vc.ru, каталоги бесплатных/open-source инструментов. Открытый исходный код и тезис «файлы не уходят на сервер» хорошо работают как инфоповод.

## Языки

English (основной, без префикса в URL), русский, español, português (BR), deutsch, français, 简体中文. URL вида `/compress-pdf`, `/ru/compress-pdf`, `/de/compress-pdf`.

Пользователю с другим языком браузера показывается ненавязчивая плашка «Эта страница доступна на русском». Автоматического редиректа нет, чтобы не мешать поисковикам.

**Добавить язык** (например, турецкий):

1. Скопировать `src/i18n/en.ts` в `src/i18n/tr.ts` и перевести строки. TypeScript проверит, что ни один ключ не пропущен.
2. Добавить `'tr'` в `LOCALES` и `LOCALE_INFO` в `src/i18n/locales.ts` и в `DICTS` в `src/i18n/index.ts`.

> Совет: у запросов «compress pdf» огромный объём на индонезийском, турецком и хинди. Если цель трафик, это следующие кандидаты.

## Дизайн

Сознательно уходит от шаблонного «сгенерированного» вида (фиолетовые градиенты, эмодзи-иконки, центрированный герой с рядом «пилюль», сетки одинаковых карточек):

- тёплый «бумажный» фон, почти чёрный текст и один акцентный цвет (сигнальный оранжевый); основные кнопки чёрные;
- шрифт [Onest](https://fonts.google.com/specimen/Onest) (латиница + кириллица, лежит на своём домене), размеры файлов и форматы моноширинным;
- выравнивание по левому краю, тонкие линии вместо теней, таблицы и списки вместо карточек;
- инструмент выглядит как окно приложения: сверху выбор формата, справа настройки, файлы списком с размерами «до → после».

Все цвета заданы токенами в начале `src/styles/global.css` (светлая и тёмная палитры), акцент меняется в одном месте.

## Стек

- [Astro](https://astro.build) 7: статическая генерация, i18n-маршруты, CSP. Интерактив на [Preact](https://preactjs.com) (3 КБ).
- В dev-режиме лениво загружаемые зависимости (pdf-lib, pdf.js, libheif) перечислены в `optimizeDeps.include`, а dev-тулбар Astro отключён. Иначе Vite пересобирал зависимости посреди сессии: в консоли появлялось `504 (Outdated Optimize Dep)`, страница перезагружалась, и выбранные файлы терялись.
- Изображения: [jSquash](https://github.com/jamsinclair/jSquash) (WebAssembly-сборки MozJPEG, libwebp, libavif, oxipng, ресайз Lanczos3) и собственный квантизатор палитры (`src/engine/quantize.ts`: median cut + k-means + дизеринг Флойда–Стейнберга, MIT, без GPL-зависимостей).
- PDF: [pdf-lib](https://pdf-lib.js.org) для сжатия (пережатие встроенных изображений, удаление мусора, object streams) и сборки из картинок; [pdf.js](https://mozilla.github.io/pdf.js/) для рендера страниц.
- HEIC: libheif через [heic-to](https://github.com/hoppergee/heic-to). Safari декодирует HEIC сам.
- Без бэкенда. ZIP собирается своим маленьким модулем без копирования файлов в памяти.

```
src/
  engine/            обработка файлов (выполняется в браузере)
    processor.worker.ts  Web Worker: точка входа
    pool.ts              пул воркеров (параллельная обработка)
    image.ts             декодирование/ресайз/кодирование изображений
    quantize.ts          палитра для PNG (как TinyPNG)
    pdf.ts               сжатие PDF, картинки → PDF
    pdf-render.ts        PDF → картинки (pdf.js)
    heic.ts, zip.ts, formats.ts
  components/app/    интерфейс инструмента (Preact)
  components/        шапка, подвал, FAQ, карточки (Astro)
  i18n/              словари 7 языков
  pages/             главная, страницы инструментов, about, sitemap, robots, llms.txt
  tools.ts           список инструментов (добавить инструмент = добавить запись)
  site.ts            название бренда и цвет
public/              _headers, service worker, манифест, иконки
tests/               e2e-тесты Playwright на реальных файлах
```

## Запуск

Требуется Node.js 22.12+.

```bash
npm install
npm run dev          # http://localhost:4321
npm run build        # сборка в dist/
node scripts/serve.mjs   # предпросмотр dist/ с боевыми заголовками из _headers
npm test             # проверка типов + сборка + e2e-тесты в Chromium
```

E2E-тесты прогоняют реальные сценарии: сжатие JPG/PNG/PDF (результат меньше и валиден), конвертации в WebP/AVIF/JPG/PNG, JPG → PDF (порядок и ориентация страниц), PDF → JPG, ZIP-архив, ошибки на неподходящих файлах. Заодно они проверяют, что за время работы **нет ни одного запроса за пределы сайта** и ни одного нарушения CSP.

## Деплой (Cloudflare Pages, бесплатно)

1. Залить репозиторий на GitHub → Cloudflare Dashboard → Workers & Pages → Create → Pages → Connect to Git.
2. Build command: `npm run build`, output directory: `dist`.
3. Environment variables: `SITE_URL=https://ваш-домен.com`, `NODE_VERSION=22`.
4. Подключить свой домен в разделе Custom domains.

`public/_headers` Cloudflare Pages подхватывает автоматически. Netlify читает тот же формат. На Vercel заголовки нужно перенести в `vercel.json`. GitHub Pages не подходит: там нельзя задать заголовки.

**Ребрендинг**: название в `src/site.ts` и `public/manifest.webmanifest`, затем `node scripts/make-images.mjs` перерисует иконки и OG-картинку.

## Честные ограничения

- Максимальный размер файла ограничен памятью устройства. На компьютере это сотни мегабайт, на старых телефонах меньше.
- PDF сжимается за счёт изображений внутри (сканы, фото: −50…90%). Чисто текстовые PDF уже компактны (−5…15%). Ghostscript мог бы ужать некоторые векторные PDF сильнее, но он под AGPL и весит ~15 МБ. Его можно добавить как опциональный режим «максимум».
- Конвертация Word/Excel → PDF в браузере потребовала бы LibreOffice в WebAssembly (~50 МБ). Здесь нужен сервер или отдельное решение.
- Кодирование AVIF медленнее остальных форматов (секунды на фото).

## Идеи для развития

Объединение/разделение/поворот PDF (pdf-lib это умеет), удаление пароля с PDF, GIF/видео (ffmpeg.wasm), сжатие под целевой размер («сделать PDF меньше 1 МБ»), ресайз по процентам, обрезка, Ghostscript-режим, ещё языки (id, tr, hi, ja, ar с RTL).
